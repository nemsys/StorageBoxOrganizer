# Преводи

Интерфейсът се показва на английски и на български. Тази папка съдържа всичко:

| Файл | Какво съдържа |
| --- | --- |
| `en.json`, `bg.json` | Всички низове, по един ключ на низ |
| `terms.en.json`, `terms.bg.json` | **Речникът** — основните понятия (кутия, вещ, етикет, снимка) |
| `index.jsx` | Логиката: `TranslationProvider`, `useTranslation()`, `translate()` |

Езикът се пази в `localStorage` под ключ `lang`. При първо отваряне се взима от
браузъра (`bg*` → български, иначе английски). Превключвателят е в менюто с
настройки, най-отгоре.

---

## Как да сменя дума (напр. „кутия“ → „контейнер“)

Редактираш **само** `terms.bg.json`. Низовете никога не съдържат самата дума —
те сочат към речника, затова една редакция стига:

```json
"box": { "one": "контейнер", "counted": "контейнера", "many": "контейнери",
         "the": "контейнера", "theSubj": "контейнерът", "theMany": "контейнерите",
         "g": "m" }
```

**Не забравяй `g`** — това е родът. „Кутия“ е женски (`f`), „контейнер“ е мъжки
(`m`). От него зависят всички прилагателни и местоимения: „Кутията е изтрит**а**“
става „Контейнерът е изтрит“, „вещи в не**я**“ става „вещи в него“. Смениш ли
думата, но забравиш рода, текстът остава граматически грешен — затова смени и
двете наведнъж.

Формите означават:

| Форма | Кога се ползва | Пример |
| --- | --- | --- |
| `one` | брой 1, или без член | „Добави **кутия**“ |
| `counted` | след число (бройна форма) | „5 **етикета**“ — не „етикети“ |
| `many` | множествено без число | „Всички **етикети**“ |
| `the` | с определителен член, като допълнение | „Изтрий **кутията**“ |
| `theSubj` | с определителен член, като подлог | „**Етикетът** е изтрит“ |
| `theMany` | множествено с член | „Назад към **кутиите**“ |
| `g` | род: `m` / `f` / `n` | |

`the` и `theSubj` се различават само при мъжки род (пълен и кратък член:
„етикетът“ / „етикета“). При женски и среден са еднакви, но ги попълни и двете —
иначе следващата смяна на дума ще счупи изреченията.

## Как да добавя нов низ

1. Добави ключа и в `en.json`, и в `bg.json` — задължително и в двата.
2. Използвай го в компонента:

```jsx
import { useTranslation } from '../translations';

const { t } = useTranslation();
<h2>{t('box.title')}</h2>
```

**Не пиши думата „кутия“ в низа.** Вместо това я вземи от речника:

```json
"box.editTitle": "Редактирай {{box.the}}"
```

### Изречение с кликаема част

Ако част от изречението е линк или бутон, тя става **отделен ключ** — иначе
целият текст изглежда като един блок и потребителят не вижда къде да натисне:

```json
"auth.noAccount": "Нямаш профил?",
"auth.noAccountAction": "Регистрирай се"
```

**Не преизползвай ключа на бутона за действието.** На български двете често са
различни части на речта: бутонът е съществително (`auth.signIn` = „Вход“), а
подканата е повелително наклонение („Влез“). „Вече имаш профил? Вход“ е грешно.

### Стойности по време на изпълнение

```json
"box.editAria": "Редактирай {{name}}"
```
```jsx
t('box.editAria', { name: box.name })
```

Едносъставна препратка (`{{name}}`) идва от параметрите; двусъставна
(`{{box.the}}`) — от речника.

### Множествено число

Пиши два ключа със суфикси `_one` и `_other` и подай `count`:

```json
"item.count_one":   "{{count}} {{item.one}}",
"item.count_other": "{{count}} {{item.counted}}"
```
```jsx
t('item.count', { count: items.length })   // → "1 вещ" / "5 вещи"
```

### Съгласуване по род

Ако низът съдържа прилагателно или местоимение, което се съгласува с понятието,
не го пиши направо — вземи го от таблицата `forms` в речника, като използваш
понятието като префикс:

```json
"box.deletedToast": "{{^box.theSubj}} е {{box.deleted}} заедно със съдържанието"
```

`{{box.deleted}}` не съществува в записа за `box`, затова се търси в `forms.deleted`
и се избира формата за рода на понятието → „изтрита“ (ж.р.). Ако утре „кутия“
стане „контейнер“ (м.р.), същият низ ще даде „изтрит“.

Нужното прилагателно го няма в `forms`? Добави го — трите форми наведнъж:

```json
"archived": { "m": "архивиран", "f": "архивирана", "n": "архивирано" }
```

**Съвет:** повелителните форми („Добави“, „Изтрий“) и отглаголните
съществителни („Изтриване на…“) не се съгласуват по род. Предпочитай ги — така
таблицата `forms` остава малка. Множествените прилагателни („изтрити“, „нови“)
също са еднакви за трите рода и се пишат направо.

### Главна буква

`{{^box.one}}` изписва стойността с главна буква: „кутия“ → „Кутия“. Ползва се,
когато понятието започва изречението или е заглавие.

## Проверка

```bash
npm run translations:check
```

Гърми при:

- ключ, който го има в единия език, но не в другия;
- `{{препратка}}`, която речникът не може да разреши (печатна грешка във формата,
  липсваща форма за даден род);
- параметър, използван в единия език, но не в другия за същия ключ;
- ключ, извикан с `t('...')` в кода, но липсващ в `en.json`.

Предупреждава (без да гърми) за ключове и форми, които вече не се ползват никъде.

---

## Какво **не** се превежда

- Съдържанието на потребителя: имена на кутии, вещи, описания, етикети.
- Датите — `dateUtils.js` ги форматира числово (`12.03.2026`), еднакво за двата
  езика. Липсваща дата се показва като тире.
- Съобщенията от Firebase — `AuthModal.jsx` превежда кодовете за грешка
  (`auth/wrong-password` и т.н.) през ключове `auth.error.*`, вместо да показва
  английския текст от SDK-то.

---

## Странична бележка: „i18n“

В други проекти тази папка обикновено се казва `i18n` — съкращение от
*internationalization* („i“ + 18 букви + „n“). Тук е наречена `translations`,
защото е по-ясно. Ще срещнеш и `l10n` (*localization*) — подготовката на кода е
i18n, самият превод за конкретен език е l10n.
